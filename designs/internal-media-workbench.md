# OmniHub 内网创作与作品资产功能设计

> 2026-09-20 更新。适用场景是个人使用的 OmniHub，连接公司提供的图片、视频生成服务。接口依据[公司飞书文档](https://huixuanjiasu.feishu.cn/docx/O6mpd0DVko8yn9x2pD3c3IIvn1c)。真实认证已被创建接口接受；额度、生成完成及结果入库仍待验证。

## 当前实施状态

OmniHub 已增加创作台、作品视图和独立的媒体接口设置。可从提示词、X 收藏和既有作品进入创作台，选择参考素材，提交图片或视频任务；任务状态会保存在数据库，完成后把结果文件保存到站点私有目录。作品视图支持上传、预览、下载、搜索、评分、备注、标签，以及从图片继续改图或生成视频。图片、Seedance、Wan 3 的文档参数已接入；Happy Horse 目前开放文生视频，其余模式需要生成服务能访问素材 URL 后再接。

本地模拟服务已跑通认证信息保存、素材上传、幂等提交、查询、结果入库和版本关联；网页也走通了相同流程。媒体测试 3 项通过。zane 的个人认证与文档中的 HTTP 地址已写入本机配置，`sys_token` 留空。真实查询接口对不存在的任务 ID 返回业务码 `1004`；真实认证测试中，假认证返回 `1002`，已保存的认证返回 `code=0` 和任务 ID。该请求使用了无效模块和空参数，但服务端仍创建了任务，因此它只能证明创建请求被接受，不能证明生成成功或没有消耗额度。探测任务的上游 ID 未留存，状态与额度影响无法追查；后续真实验收通过站内任务保存上游 ID。真实图片、视频结果及入库尚未验收。

## 要完成的事情

在 X 收藏中看到一组有用的图片提示词时，用户应当能查看原帖和效果图，选用其中的提示词和参考图，生成自己的图片或视频。生成后的作品进入资产库，能找回、放大查看、比较版本、继续改图或用于下一次生成。用户自己上传的图片和从 ChatGPT 下载的作品，也要能进入同一个资产库。

这条链路里，X 帖子提供来源，提示词提供可复用的方法，作品保存一次具体结果。同一话题的多个帖子可以归入一个主题，仍分别保留作者、原文、图片和链接；它们的提示词及作品也分别可追溯。

现有 OmniHub 已有收件箱、提示词／资源／知识资产库、提示词的来源与图片字段、AI 文字对话。提示词的“试跑”目前只是把文本带到对话页；尚无媒体生成任务、作品文件存储和作品视图。本方案在这些现有入口上扩展。

## 从收藏到作品

```text
X 收藏详情 ──“用于创作”──┐
提示词资产 ──“生成图片/视频”──┼─→ 创作台 ─→ 生成任务 ─→ 作品资产
手动新建 / 上传作品 ────────┘       ↑                │
                                     └── 从作品继续改写/制作视频
```

1. **选择材料。** 从收藏进入时，显示原帖、完整链接、作者、相关提示词和效果图；从提示词进入时，载入已保存的原文、整理版和模型备注。用户选择真正要发送的提示词与参考图。帖子中的效果图默认仅供查看，不自动作为输入上传。
2. **编辑生成内容。** 创作台保留一份可编辑草稿。可切换图片／视频、服务与模型；尺寸、时长、参考图数、首尾帧等控件按所选模块的已核对能力显示，不展示当前模块不支持的选项。原始提示词永远保留，提交时另存本次使用的文字及参数快照。
3. **提交与跟踪。** 提交前显示所选服务、模型、尺寸或时长，以及能取得的费用估计；文档尚未给出价格，当前应明确显示“费用待确认”，不能把返回的 token 数当作价格。每次点击只创建一个可追踪任务，返回任务编号与状态。页面关闭或刷新后，任务仍可查；超时先查原任务状态，不自动重新提交。
4. **收取结果。** 图片完成后保存原图和预览图；视频保存文件或可长期访问的受控副本，并生成封面。一个任务产生多个结果时，每个结果成为独立作品，彼此仍关联同一个任务。失败任务保留错误摘要与原始输入，供用户检查后手动重试。
5. **再次使用。** 作品详情可查看原尺寸图片、视频播放器、使用的提示词、参考图、服务参数、原始帖子和同组版本。可下载、标记喜欢、复制提示词、以图改图，或将图片带入视频创作。

创作台作为独立工作视图，从原有 AI 提炼台和资产详情进入；文字对话的“试跑”继续保留。媒体操作在按钮上明确写成“生成图片”“生成视频”，不会用同一个“试跑”混淆文字对话与实际生成。

当内网工具能力已核准，TypeSafe 可根据媒介类型、参考素材和已公开的模型能力，在有限候选中建议模型或下一步动作，并展示建议依据；最终选择与提交仍由用户完成。路由只发送必要的非敏感特征，不传内网图片、凭证或完整私人原文。TypeSafe 不可用时仍能手动选模型与参数。

## 飞书文档确认的接口

文档给出两条统一 HTTP 接口。`POST /support/open_api/create` 接受 `authentication`、`module`、`args` 与可选的 `remark`；有本地参考素材时走 multipart 上传，没有文件时可以传 JSON 和可访问的素材 URL。创建成功返回记录 `id` 与 `init` 状态。`POST /support/open_api/query` 接受一组任务 `ids`，返回 `init / queued / generating / success / failed`、错误摘要，以及成功后的结果 URL。结果链接可能失效，文档建议保存任务 ID 并重新查询以取得新 URL。两个接口均返回业务 `code` 和 `msg`，不能只看 HTTP 200。

| 模块 | 已写明的能力 | 对应创作台入口 |
| --- | --- | --- |
| `image` | `nano-banana-pro`、`gpt-image-2`、`seedream-5.0-pro`、`gpt-image-2-flare`；文生图与参考图生成，尺寸和比例按模型限制 | 生成图片；选用效果图时明确标记为参考图 |
| `seedance` | 文生视频、首帧／首尾帧、图片／视频／音频参考；`seedance2.0`、`seedance2.0-mini`、`seedance2.5` | 生成视频；后续支持多素材创作 |
| `hh1` | 文生视频、首帧、参考图及视频编辑；模式决定图片和视频输入规则 | 生成视频；从作品继续创作或编辑 |
| `wan3` | 文生视频、首尾帧及混合参考；额外支持单份文档或网页链接作为素材 | 生成视频；复杂素材模式放在后续阶段 |

图片模型的参考图上限按模型为 8、10 或 16 张。视频模块的素材数量、时长、比例和人脸处理要求差别较大，界面应先选模块和模式，再校验输入。尤其是 Seedance 的含人脸素材要求填写对应处理参数；不得用一套通用表单把所有参数无差别发送。文档有一些示例与字段说明不一致的地方，实际请求以经管理员确认的字段合同和服务端返回为准。

查询接口的无认证探测中，空 `ids` 返回业务码 `1001`，不存在的 ID 返回 `1004`（记录不存在），HTTP 均为 200。当前服务端适配器也已连通真实查询接口，能把 `1004` 转为站内错误。创建接口的认证差异另由真实请求验证；查询探测不能证明费用、生成结果或 MCP 可用。

## 资产库怎么呈现

现有“提示词｜资源｜知识”增加“作品”。提示词卡片继续展示原帖效果图与用途；生成结果只进入作品视图，以免一条提示词复制成多条。作品视图默认按创建时间倒序，允许按评分或喜欢程度排序，提供图片／视频／上传、主题、模型、标签和来源筛选；搜索同时覆盖作品标题、备注、提示词与来源作者。

图片卡片使用可辨认的预览尺寸，按原图比例裁切或完整显示；单击打开右侧详情，再单击进入可缩放的原图查看。视频卡片有封面、时长和播放入口。卡片只显示缩略图、标题、类型与少量状态；来源、参数和版本信息放在详情中。文件缺失时显示“文件待恢复”并提供原任务入口，不显示空白文章或假缩略图。

作品详情按“预览 → 本次提示词与参考图 → 来源与关联版本 → 参数和备注”排布。一个主题可以收纳多个作者讲同一工具或技法的帖子，作品按“来自哪条帖子、哪份提示词、哪次生成”关联；主题归并不合并或覆盖原始内容。用户可给作品补标题、用途、评分和复现备注。版本通过“从此作品继续创作”建立父子关系，不靠覆盖文件表示更新。

手动上传用于已有作品、外部工具生成的图片和视频。上传时可选择关联提示词或 X 来源；没有来源也允许保存。外部作品标记为“上传”，不伪装成内网生成结果。仅有文字而没有媒体文件的内容仍属提示词或知识，不创建空作品卡。

## 公司网络与 GPT 账号

浏览器只调用 OmniHub 自己的 API。服务端负责调用公司生成服务，凭证保存在本机受权限限制的数据库中；浏览器、静态页面和作品分享链接都不携带凭证。飞书文档目前只给出明文 HTTP 公网 IP，并要求在创建请求中发送 `authentication`。用户知悉风险后要求接入该地址，服务端只对文档中的准确地址放行公网 HTTP，其他公网 HTTP 仍被拒绝。每次提交都可能让中间网络设备读取认证，页面会明确提示；服务方提供 HTTPS 或加密通道后应切换。浏览器不得直连公司接口。

**推荐先按 HTTP 任务协议设计服务端适配器。** 它用一套创建／批量查询接口覆盖四个模块，最适合 OmniHub 保存任务、恢复状态并下载作品。现有 Codex 配置中虽有图片和视频 MCP 的 HTTPS 连接，但本次会话未加载其工具，当前网络对两个 MCP 地址的 TLS 握手也未成功；尚不能证明两边功能与文档完全相同。服务端适配器保留传输边界，之后若 HTTPS MCP 在公司网络中稳定可用，再核对工具合同并替换具体调用方式，不改变创作台和作品数据。

文档规定 `authentication` 为必填的用户认证信息；个人使用可不填 `sys_token`，作为平台对组内外提供服务则需另行取得。OmniHub 当前只有个人白名单账号，但网站形态可能被服务方视作平台，接入前应由管理员确认口径。查询接口示例未要求认证，OmniHub 仍必须只允许登录用户查询自己保存的任务 ID，不能把任意 ID 转发给前端。

创作台区分“接口可达但认证未验证 / 可提交 / 需要公司网络 / 未授权 / 服务异常”。无费用的查询探测只能确认网络，不能验证认证。离开公司网络时，仍可看已保存的本地作品、编辑草稿和上传文件；生成按钮不可提交。网络恢复后用户再主动提交。网络中断期间已提交的任务以服务端记录为准核对，不擅自重复收费。

OmniHub 的登录与生成服务凭证分开管理。ChatGPT 登录在支持的第三方应用中用于身份认证，不会凭登录自动获得生成 API 的额度或权限；ChatGPT 订阅与 API 计费也分别管理。因此当前设计优先接公司内网 MCP。用户在 ChatGPT 网页生成并下载的图片，可通过手动上传入库，标记来源为“ChatGPT 上传”；未来如有正式授权的媒体 API，再把它接成另一个服务适配器。[OpenAI 登录说明](https://help.openai.com/en/articles/20001410-sign-in-with-chatgpt)、[OpenAI 账单说明](https://help.openai.com/en/articles/9039756-managing-billing-for-chatgpt-and-the-api-platform)。

## 数据与接口边界

沿用现有 `inbox` 和 `prompts`。新增生成任务与作品记录，至少保存以下信息：

| 对象 | 必要字段 | 用途 |
| --- | --- | --- |
| 生成任务 | 用户、媒体类型、服务与模型、本次提示词快照、参数、参考素材 ID、来源 ID、状态、服务任务 ID、错误摘要、创建与完成时间 | 刷新后恢复状态、防重复提交、还原生成过程 |
| 作品 | 用户、任务 ID 或“手动上传”、文件与缩略图的私有路径、类型、尺寸或时长、标题、主题与标签、评分、父作品 ID、备注 | 展示、搜索、版本关联和再次使用 |
| 来源关联 | 作品 ID、提示词 ID、X 收藏 ID、原链接；任一项可缺 | 返回原文和效果图，保留出处 |

数据库只存元数据和文件路径；原文件、预览图和视频封面放在 `public/` 以外的私有目录。下载与预览均经过登录鉴权和用户 ID 校验，避免猜测 URL 读到别人的文件。服务返回短期链接时，后台在有效期内将结果复制到私有存储并核验大小、类型和校验值；不能只保留即将失效的 URL。上传限制类型与大小，并处理路径穿越和恶意文件。作品与任务各自保留稳定 ID；删除前需要说明它是否被其他版本或提示词引用。

站内接口保持薄层：读取连接状态、创建任务、查询任务、列出／读取作品、上传作品、读取受保护的媒体文件。适配层把 `module + args`、JSON／multipart 上传、批量查询、结果下载和错误映射成站内一致的任务状态，并保存上游任务 ID。提交时先持久化站内任务和幂等键，再调用创建接口；若请求超时而没有收到上游 ID，标记为“待人工核查”，不能盲目再发一次生成。结果的 `url` 仅作为下载来源，不能直接暴露给资产库列表。

## 实施顺序与验收

1. **先建作品库与手动上传。** 从提示词或 X 收藏进入创作草稿，支持图片／视频上传并关联来源。验收时，上传一张图和一个视频，刷新后仍可预览、下载、搜索并返回原帖；另一账号不能读取文件。
2. **验收真实 `image` 生成。** JSON 文生图与参考图 multipart 已在本地模拟服务中通过；公司文档 HTTP 地址和个人认证已接入。用户已授权并提交一次 `nano-banana-pro` 1K 文生图任务，创建接口返回 `init` 并保存了远端任务 ID；后续查询仍为 `init`，尚无结果文件。继续查询这一个任务，完成后核对文件本地化、详情关联、网络中断和刷新恢复，不重复提交。额度和价格仍需服务方说明。
3. **接 `seedance`，再按需接 `hh1`／`wan3`。** 先做文生视频和单图首帧，后加多参考素材与视频编辑。验收时，从既有图片发起视频，完成后能在作品详情里往返查看两者；超时或重开页面不会产生第二次提交。
4. **再做批量组织。** 等作品积累后，再加批量主题归类、相似作品查找与项目关联；先用真实作品检验筛选和命名是否够用。

目前已在本机实现并启动页面，真实接口地址和个人认证已配置，唯一一笔真实生成任务已提交并处于上游 `init` 状态。飞连网页版可通过飞书登录；桌面客户端登录页未显示登录方式，其接口响应出现 HTML 代替 JSON 的错误，尚未建立 VPN 连接。剩余验收是查询原任务直至有结果、结果入库，以及服务方提供的额度与安全传输方案。
