# OmniHub 信息流与项目工作台方案

> 2026-09-19，产品方向草案。用于修订 [第二大脑改造方案](second-brain-redesign.md) 中“收件箱作为默认首页”的安排；现有收件箱和资产库继续作为实现基础。

## 要解决的事

用户会在 X 和信息流中保存提示词、工具、文章与项目线索。数量增加后，单纯收藏很难回答“我为什么留下它”“现在能用在哪个项目”“何时再看”。OmniHub 应让新信息有去处，也让已保存的东西在需要时重新出现。

现有代码已具备信息流、一键收录、收件箱、提示词／资源／知识资产库，以及 TypeSafe 的内容类型建议。它还缺少项目、下一步动作、跨类型搜索和定期回顾。当前 TypeSafe 判断的是内容类型，尚未判断它与用户工作的关系。

## 四个主要入口

| 入口 | 打开时看到什么 | 主要动作 |
| --- | --- | --- |
| 工作台，登录后默认 | 正在做的项目、每个项目的一步行动、到期回顾的收藏、待处理数量 | 继续做、回顾、关联资料 |
| 信息流 | 外部新内容，按来源浏览 | 存入收件箱 |
| 收件箱 | X 收藏、信息流保存、手动记录的原始内容 | 稍后读、关联项目、存为资料、忽略 |
| 资料库 | 可复用的提示词、资源和知识，支持统一搜索 | 找回、打开、复制、用于项目 |

AI 提炼台和工具箱保留为辅助入口。工作台只放真正会改变下一步行动的内容，避免用统计卡填满首页。

## 信息怎样流动

```text
X 收藏 / 信息流 / 自己的想法
              ↓
       原文与来源先保存
              ↓
  TypeSafe 建议下一步用途与关联项目
              ↓
稍后读 / 存资料 / 关联项目 / 忽略
              ↓
  工作台按项目、回顾时间和搜索再次呈现
```

“内容类型”和“处理状态”分别保存。一篇文章可以是知识资料，也可以同时为某个项目提供参考。项目不作为第四种资产类型；它记录要达成的结果，并通过关联记录使用哪些资料。一个资料允许关联多个项目。

项目第一版只需名称、目标、状态（想法／进行中／暂停／完成）、一条下一步行动和关联资料。把收藏转成项目行动需要用户确认，避免每条 X 帖子自动产生待办。自己的新点子也能直接建成“想法”，不必先伪装成一条收藏。

## TypeSafe 的位置

对新条目保留现有的提示词／资源／知识判断，再增加一个独立判断，建议“稍后读、作为资料保存、关联现有项目、可能是新项目想法、暂时无用”。仅在“关联项目”有足够证据时，从当前项目候选中选择一个，否则明确返回“无匹配”。模型给出建议和概率，代码保存原始判断，用户决定最终动作。

摘要、改写和自由文本的下一步行动可以由通用模型生成；TypeSafe 负责从有限选项中作判断。服务故障时，原文继续入库，手动处理仍可用。阈值应在用户确认过的收藏样本上校准，不能把模型的 confidence 当成正确率。

## 旧收藏与回顾

本机已有 X 收藏导出，最近一次文件修改于 2026-07-03。`bookmarks.posts.jsonl` 有 100 个物理行，其中 98 行可独立解析，另 2 行对应的记录需要先检查。导入时应以帖子 ID 去重，先核对总数与原文完整性。旧收藏先进入可搜索的待回顾区，每次只展示少量条目；新收藏正常进入收件箱。

回顾区按“用户标记的稍后时间”和“与进行中项目相关”排序。没有项目关联的旧收藏也能通过统一搜索找回。工作台每次只显示少量到期项，让回顾成为可完成的动作。

## 实施顺序与验收

1. 增加项目与资料关联，做工作台首页。验收时，新建一个项目，给它设置下一步行动，将一条收件箱内容关联进去；刷新后仍能在工作台看到。
2. 增加统一搜索与稍后回顾。验收时，不知道内容被分到哪里，也能用原文关键词找到；到期项能重新出现并标记已处理。
3. 修复旧 X 导出的解析问题，再做幂等的分批导入。验收时，导入总数与源文件一致，重复导入不产生重复条目，不把旧收藏一次堆进日常收件箱。
4. 将 TypeSafe 扩展到用途与项目匹配。用一组用户确认过的样本评估建议；不确定时保留人工选择。

这个顺序先让用户能把收藏用于项目，并在需要时找回来，再扩大自动输入量。
