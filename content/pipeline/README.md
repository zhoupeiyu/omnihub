# 收藏整理与 X 关注

这套实现将公开资讯、个人收藏和关注动态分开保存。只有主动收藏的内容进入个人整理队列，只有明确发布的整理结果对访客展示。

## 三个入口

| 入口 | 数据去向 | 整理方式 |
| --- | --- | --- |
| AIHOT 资讯 | 原有接口与缓存 | 保留上游评分、精选理由，不自动入库或重新计分 |
| X 来源、手动收录、主动保存的资讯 | `inbox` 原文与版本快照 | 分类、分项评分、同问题归组、中文整理和引用核验 |
| 我的关注、关注热点 | 独立的 `x_watch_*` 表 | 增量采集、中文摘要、事件归组；点收藏后才进入 `inbox` |

同一个 X status ID 重复收藏时保留已有原文。导入快照不完整时，不根据本次缺少的帖子删除旧收藏。

## 个人收藏处理规则

原文、图片地址、外链与引用帖保留在来源快照中。正文变化生成新快照；重复导入相同正文不会重复调用模型。

TypeSafe 先给出结构化分类。类型不确定或材料可能不完整时，再由现有 Claude API 细读。分类支持多种资产并存，例如仓库教程同时包含仓库与方法。只有具体任务的完整指令才算提示词，常驻 Agent 规则和一般建议归入方法。

评分分为可复用内容、信息增量、材料依据、需求相关、可操作性五项，每项 0 到 10 分，按资产类型的固定权重换算为百分制。各项都有文字依据。信息增量只针对当前材料判断，并未和整个收藏库做新颖性比较。分数不代表事实可信度，也不代表投资价值。

完整但分类有歧义的材料可以生成摘要和评分草稿，暂不自动归入知识库。缺少正文、回复里的提示词或必要图片信息时，保留待补材料状态，不以零分替代未知。

每个整理段落必须带原文中的连续摘录。模型再次检查结论与引用是否一致；发现问题时最多修订一次，再不通过就留待复核。这是对来源一致性的检查，不是对现实事件的独立查证。

只有同一个具体问题才合并为知识文章。相关主题、同一币种或相同关键词不够。合并文章保留多个来源，并在原文变化或隐藏后停止公开旧结果。

通过核验且达到 65 分的最新结果进入“精选待读”，最多显示 50 条。精选不等于发布。zane 可以查看全文和评分依据，再决定是否发布。合并文章需要所有参与来源的整理结果分别获准发布。已有人工归类和已复核归类不被自动覆盖。

仓库结果发布时只增量加入仓库及来源关系，不覆盖已有的官方简介、分类或保存入口。新仓库的细分用途仍可能需要人工补充。

## 本地启用

服务启动后，zane 在“X 来源”的“收藏整理”中选择本轮范围。默认先处理 50 条后暂停，也可以选 100 条或全部及以后新增收藏。私有和未公开材料默认不送模型，需单独勾选授权。

现有模型配置由服务端读取。可使用本机 Claude 配置文件，也可通过部署环境的密钥管理注入以下变量；不要把密钥写进仓库、浏览器或本文。

- `OMNIHUB_CLAUDE_SETTINGS`：现有 Claude 配置文件路径。
- `OMNIHUB_CONTENT_BASE_URL`、`OMNIHUB_CONTENT_MODEL`、`OMNIHUB_CONTENT_API_KEY`：可选的服务端覆盖项。
- `TYPESAFE_API_KEY`：结构化分类服务配置。
- `OMNIHUB_CONTENT_DAILY_CALLS`、`OMNIHUB_CONTENT_HOURLY_CALLS`：默认最近 24 小时 40 次、最近一小时 12 次调用。
- `OMNIHUB_CONTENT_WORKER=false`：停用常驻处理。页面手动处理仍要求账号已启用整理。

队列保存各阶段结果、调用记录和重试状态。处理失败会有限重试，成功阶段使用已保存的结果。规则版本变化后需 zane 重新启用，不自动重跑历史材料。调用次数上限不是金额报价。

## X 账号监听

在“信息流 → 我的关注”保存账号、分组、间隔，以及是否包含回复或转发。保存名单不会发起采集。

真实采集需要服务器配置 `SOCIALDATA_API_KEY`、`OMNIHUB_X_WATCH_ENABLED=true`，并由 zane 设置正数的每日请求上限与启用账号。中文摘要另需 `OMNIHUB_X_WATCH_ANALYSIS=true`，默认每 24 小时最多 20 次模型调用。未确认账号名单、供应商和费用范围前，应保持关闭。

采集使用固定 SocialData 搜索接口。每页保存游标，完成全部分页后才推进账号水位；异常项跳过，反复失败的游标会重扫，帖子按 ID 去重。账号暂停或配置变化会使在途结果失效。分析任务使用数据库租约避免并发重复处理。

热点只统计关注范围内最近 48 小时的同一事件，至少两个不同原始来源账号参与；同一原帖的转发按原作者去重。热度按时间衰减，不是全网热榜，也不代表消息可靠。观点、推广和未经证实的内容会单独标识。

## 当前边界与验收

目前整理依据是已保存正文、引用文字及媒体信息。不会假装看过图片，也不会自动抓取任意外链正文或完整 README。缺失材料应后续补齐后重新整理，不能用模型猜测填充。

本次开发只在隔离数据库副本做真实模型抽样。本地启动新版前已备份数据库，新增处理表后，1857 条原收藏的完整行校验值保持一致；原文和已有分类没有改写。生产服务未更改。X 采集使用合成响应验证，尚未接入真实账号或产生采集费用。合成页面数据均标记为“界面验收示例”。

首轮共检查 6 条公开收藏，3 条产生了中文全文和分项评分草稿。模型对其中结论给出了支持判断，但置信度或引用问题仍未达到自动通过标准，因此没有自动发布，也未启动全库处理。另一类样本缺少回复中的提示词或正文，保留待复核。后续应继续校准真实材料上的误拦截率，不能只凭离线测试通过就启用无人值守全量处理。

定向验证命令如下，不会调用外部模型或写入正式数据库。

```sh
node --test tests/content-*.test.mjs tests/x-watch.test.mjs tests/knowledge-public-api.test.mjs tests/knowledge-store.test.mjs tests/library-curation.test.mjs tests/x-import-*.test.mjs tests/http-performance.test.mjs tests/web-build.test.mjs
```

真实模型抽样脚本 `scripts/check-content-pipeline.mjs` 必须显式指定隔离副本目录和 `--run`，仅选择公开收藏；最多 10 条，结束后暂停。`--diagnostics` 只记录停止原因、输出类型与用量，不输出密钥或上游完整响应。它会调用已配置的模型服务，不应放进普通测试或 CI。
